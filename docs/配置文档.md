# 配置文档 (Configuration Documentation)

本文档详细说明了 `demo/src/main/java/com/lbc_plot/config` 目录下的所有配置文件及其用途。

## 概述

该目录包含了Spring Boot应用的各种配置类，主要负责：

- 数据库连接和初始化
- 文件存储管理
- 应用属性绑定
- Web MVC配置
- 异步队列配置
- CORS跨域配置
- 项目配置绑定

## 配置文件详解

### 1. AppConfig.java
**用途**: 应用级别的通用配置
- 绑定 `app.*` 前缀的配置属性
- 管理应用的基本设置

### 2. AppProperties.java ⭐
**用途**: 应用属性绑定类
- 使用 `@ConfigurationProperties(prefix = "app")` 绑定配置
- 包含存储位置、渲染线程数、缓存启用等属性

**主要属性**:
- `storageLocation`: 存储根目录路径
- `renderThreads`: 渲染线程数量 (默认: 4)
- `cacheEnabled`: 是否启用缓存 (默认: true)

### 3. Application.java ⭐
**用途**: Spring Boot主应用类
- 应用入口点
- 包含 `@SpringBootApplication` 注解

### 4. AsyncQueueProperties.java ⭐
**用途**: 异步队列配置属性
- 配置异步任务队列的参数，包括重试策略、退避算法等

**主要属性**:
- `baseDir`: 队列基础目录 (默认: "target")
- `queueSubDir`: 队列子目录 (默认: "async_render_jobs")
- `maxAttempts`: 最大尝试次数 (默认: 10)
- `visibilityTimeoutMs`: 可见性超时 (默认: 1分钟)

### 5. CorsConfig.java ⭐
**用途**: CORS跨域资源共享配置
- 配置允许的跨域请求来源
- 支持前后端分离开发

### 6. DatabaseConfig.java ⭐
**用途**: 数据库配置管理
- 数据库连接串由 `RuntimePaths` 解析为绝对路径（`{dataRoot}/data/project.db`）
- 不再从 `db/config/database.properties` 读取（该文件只会写回相对路径，与目标冲突）

**配置属性**:
- `lbc.datasource.url`: 由 `RuntimePathsEnvironmentPostProcessor` 注入，
  默认 `jdbc:sqlite:{dataRoot}/data/project.db`；
  `application.yml` 的 `spring.datasource.url` 通过 `${lbc.datasource.url}` 引用

### 7. DatabaseInitializer.java
**用途**: 数据库初始化器
- 负责数据库表的创建和初始化
- 处理数据库迁移逻辑
- 清理旧数据库文件

### 8. filter/ 目录
**用途**: 过滤器相关配置
- 包含自定义的Servlet过滤器配置

### 9. JdbcConfig.java
**用途**: JDBC配置
- 配置数据库连接和JDBC相关设置

### 10. Main.java
**用途**: 另一个应用入口点 (可能用于特定启动方式)

### 11. ProjectConfig.java
**用途**: 项目级配置
- 管理项目特定的配置参数

### 12. ProjectConfigBinder.java
**用途**: 项目配置绑定器
- 将配置文件绑定到项目配置对象

### 13. ProjectProperties.java
**用途**: 项目属性
- 包含项目相关的配置属性

### 14. SpringBootConfig.java
**用途**: Spring Boot通用配置
- Spring Boot框架的通用配置项

### 15. SqliteDialectConfig.java
**用途**: SQLite方言配置
- 配置SQLite数据库的特定方言设置

### 16. StorageConfig.java ⭐
**用途**: 存储配置类
- 管理文件存储相关的配置参数
- 使用 `@ConfigurationProperties(prefix = "storage")` 绑定

**主要属性**:
- `backgroundsDir`: 背景图片存储目录。字段默认值 `assets/backgrounds` 会被
  `afterPropertiesSet()` 用 `AppConfig` 覆盖为绝对路径 `{dataRoot}/assets/backgrounds`，
  因此在 yml 里配置 `storage.backgrounds.dir` 不生效
- `thumbnailsDir`: 同上，最终为 `{dataRoot}/assets/thumbnails`
- `enableVersioning`: 是否启用文件版本控制 (默认: true)
- `maxFileSize`: 最大文件大小(MB) (默认: 10)
- `supportedFormats`: 支持的图片格式 (默认: `jpg,jpeg,png,gif,bmp`)
- `generateThumbnails`: 是否生成缩略图 (默认: true)
- `thumbnailWidth`: 缩略图宽度 (默认: 200)
- `thumbnailHeight`: 缩略图高度 (默认: 200)

### 17. VolumeConfig.java
**用途**: 音量配置
- 配置音频相关的音量设置

### 18. WebMvcConfig.java ⭐
**用途**: Web MVC配置
- 配置Spring MVC的相关设置
- 包括视图解析器、拦截器等

### 19. 日志配置

#### 后端日志配置
**配置文件位置**:
- 主配置文件: `demo/src/main/resources/logback-spring.xml`
- 属性配置文件: `demo/src/main/resources/logback.properties`

**主要配置项** (在logback.properties中):
- `LOG_FILE_PATH`: 日志文件路径 (默认: `logs/application.log`)
- `LOG_MAX_SIZE`: 单个日志文件最大大小 (默认: 10MB)
- `LOG_MAX_HISTORY`: 保留的历史日志文件数量 (默认: 30)
- `LOG_TOTAL_SIZE_CAP`: 总日志文件大小限制 (默认: 1GB)
- `APP_LOG_LEVEL`: 应用日志级别 (默认: DEBUG)
- `SPRING_LOG_LEVEL`: Spring框架日志级别 (默认: INFO)

**日志格式** (在logback.properties中):
- `CONSOLE_LOG_PATTERN`: 控制台输出格式 (默认: `%d{yyyy-MM-dd HH:mm:ss} - %msg%n`)
- `FILE_LOG_PATTERN`: 文件输出格式 (默认: `%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n`)

**日志文件命名规则**:
- 普通日志文件: `application.log`
- 归档日志文件: `application.log.YYYY-MM-DD.i.log` (i为序号)

#### 前端日志配置
**没有独立配置文件**：原先的 `demo/frontend/electron-react-app/log-config.json` 从未被任何代码读取，
日志配置实际硬编码在 Electron 主进程里，该文件已删除，不要再照它改配置。

**实际配置位置**: `demo/frontend/electron-react-app/public/electron.js` 顶部：
- `logDir`：安装版写 `{数据根目录}/logs`（默认 `app.getPath("userData")/logs`，设置页可以换盘；
  数据根目录不可写时退回默认目录），开发模式写 `demo/logs`
- `log.transports.file.resolvePathFn`：日志文件名，沿用后端最新日志的时间戳并加 `-2` 后缀，
  这样前后端日志文件名成对，便于一起排查
- `log.transports.file.level = "info"`、`log.transports.console.level = "debug"`
- 主进程另外用 `console` 包装 + `logStream` 把 `[main:*]` / `[renderer:*]` 写入同一个文件

**日志存储路径**:
- 安装版: `{数据根目录}\logs`，默认 `%APPDATA%\limbus-company-plot-video-generator\logs`
- 开发模式: `demo/logs`
- 文件名: `log-<YYYY-MM-DD_HH-MM-SS>.log`（前端副本为 `...-2.log`）

**日志内容**:
- 每行以时间戳开头，并带来源标识：`[main:level]`（主进程）、`[renderer:level]`（渲染进程）
- 每次运行创建新的日志文件，不覆盖历史文件

**取日志**：设置页「获取日志」按钮会把该目录下最新的 10 个文件打包成 zip 并弹保存窗口
（实现见 `public/log-export/zip-writer.js` 与 `public/electron.js` 的 `logs:export`），
用户报错时不必自己找目录。

## 配置优先级

配置的加载优先级从高到低：

1. 命令行参数
2. Java系统属性
3. 操作系统环境变量
4. `application-{profile}.yml` 文件
5. `application.yml` 文件
6. `@ConfigurationProperties` 注解的默认值

## 相关配置文件位置

- `demo/src/main/resources/application.yml`: 主配置文件
- `demo/src/main/resources/application-dev.yml`: 开发环境配置
- `demo/src/main/resources/application-prod.yml`: 生产环境配置
- `demo/src/main/resources/db/config/database.properties`: 数据库配置
- `demo/src/main/resources/storage.properties`: 存储配置（**当前没有任何代码加载它**，见下方说明）

> ⚠️ **存储配置实际生效的位置**：`StorageConfig` 用 `@ConfigurationProperties(prefix = "storage")` 绑定，
> 绑定来源只有 `application.yml` / `application-{profile}.yml`；`storage.properties` 既没有
> `@PropertySource` 也没有被 `spring.config.import` 引入，**改它不会生效**。默认 profile 下
> `application.yml` 已有 `storage:` 配置块，未配置时才回退到 `StorageConfig` 的 Java 字段默认值
> （见配置优先级第 6 条）。因此修改图片格式白名单必须同步以下四处：
>
> 1. `application.yml` → `storage.supported.formats`
> 2. `application-dev.yml` → `storage.supported.formats`
> 3. `application-prod.yml` → `storage.supported.formats`
> 4. `StorageConfig.java` → `supportedFormats` 字段默认值
>
> 四处当前均为 `jpg,jpeg,png,gif,bmp,webp`。`jpg,jpeg,png,gif,bmp` 由 JDK 自带 ImageIO 解码；
> **`webp` 由 `WebpImageDecoder`（JavaCV/FFmpeg 兜底）解码**，因为 JDK 21 的 ImageIO 不支持 WebP
> （`ImageIO.read` 对 webp 返回 null，而不是抛异常）。

## 资源路径配置指南

说明如何调整项目中使用的资源目录（背景、立绘、缩略图、音频等）。

- **最终用户**：设置 → 资源存储位置，把素材/数据库/日志整体换到别的盘（本文「在设置页切换资源位置」）
- **开发/部署**：这些目录都由 `RuntimePaths` 从"数据根目录"推导，可用 `-Dlbc.data.dir` / `LBC_DATA_DIR` 覆盖

### 可配置项位置

- 应用配置（唯一生效）: `demo/src/main/resources/application.yml` 或 `application-dev.yml` / `application-prod.yml`
- ~~备用配置: `demo/src/main/resources/storage.properties`~~（无代码加载，修改无效，仅作历史遗留参考）

### 素材路径（已统一，不要再配置相对路径）

素材、数据库、临时文件、日志的位置由 **`com.lbc_plot.common.util.RuntimePaths`** 统一解析，
是整个应用唯一的路径来源。它们全都挂在同一个"数据根目录"下面，默认值在 C 盘：

| 平台 | 默认数据根目录 |
| --- | --- |
| Windows | `%APPDATA%\limbus-company-plot-video-generator` |
| 其它 | `~/.limbus-company-plot-video-generator` |

**安装版（最终用户）的解析优先级**，由 Electron 主进程 `public/electron.js` 决定，
再把最终值通过 `-Dlbc.data.dir=<最终值>` 传给后端：

1. 命令行参数 `--data-dir=<目录>`（临时指定，例如同时维护几套数据）
2. 环境变量 `LBC_DATA_DIR`
3. 定位文件 `%APPDATA%\limbus-company-plot-video-generator\data-location.json` 里的 `dataRoot`
   ——**设置页「资源存储位置」写的就是它**，普通用户只需要用这个
4. 默认值（见上表）

后端自己（`java -jar` 直接启动、`mvn spring-boot:run`）认的优先级是：

1. 系统属性 `-Dlbc.data.dir=<目录>`（安装版由主进程传入，因此与上面的 1~3 永远一致）
2. 环境变量 `LBC_DATA_DIR`
3. 默认值（见上表）

安装版由 Electron 以数据根目录为工作目录启动后端，因此在数据根目录没被改过时，
主进程、后端、日志三者天然一致，部署时无需任何额外配置。

由数据根目录推导出的路径：

| 用途 | 路径 | 对外 URL |
| --- | --- | --- |
| 素材根目录 | `{dataRoot}/assets` | `/assets/**` |
| 音频 | `{dataRoot}/assets/audios` | `/assets/audios/**` |
| 背景 | `{dataRoot}/assets/backgrounds` | `/assets/backgrounds/**` |
| 角色 | `{dataRoot}/assets/characters` | `/assets/characters/**` |
| 数据库 | `{dataRoot}/data/project.db` | — |
| 临时素材 | `{dataRoot}/projects` | `/projects/**` |
| 日志 | `{dataRoot}/logs` | — |

### 在设置页切换资源位置（推荐给最终用户）

设置 → **资源存储位置**：显示当前数据根目录、来源、各子目录占用，并提供「更改位置…」
「恢复默认位置」「打开文件夹」。

切换流程（三步都不会删原位置的数据）：

1. 选一个新目录。校验规则：不能是磁盘根目录、不能与当前目录相同、不能与当前目录互相包含、
   必须可写；路径带空格时给出提示（个别编码工具对空格路径支持不好）。
2. 选"数据怎么办"：
   - 新目录是空的 → 选「复制现有数据」（默认，推荐）或「从空白开始」；
   - 新目录里已经有一份数据（有 `data/project.db`）→ 选「直接使用它」或「用当前数据覆盖它」。
   需要复制时会**先停后端再复制**，避免复制到写了一半的 SQLite 库。
3. 写定位文件，然后询问是否立即重启。**必须重启才生效**（后端的工作目录与数据库连接在启动时就定了）。

补充说明：

- 定位文件 `%APPDATA%\limbus-company-plot-video-generator\data-location.json` 固定留在默认目录
  （一百多字节），它记录"当前数据在哪个盘"。删掉它就等于恢复默认位置。
- 移动的是**真正占空间的数据**（素材/数据库/临时工程/日志）。Electron 自己的缓存
  （`Cache`、`GPUCache`、`Local Storage` 等，通常几十 MB）仍在默认用户数据目录，不受该设置影响。
- 原位置的数据不会被删除。定位文件里还会记下 `previousDataRoot`（迁移前的位置），
  设置页据此提示"旧位置还留着一整份数据"并提供「打开旧位置」按钮，确认新位置没问题后可以手动删掉它腾空间。
- `LBC_DATA_DIR` 或 `--data-dir=` 生效时，设置页的按钮会被禁用并说明原因：它们的优先级更高。
- 卸载时 `deleteAppDataOnUninstall: true` 只删默认目录；把数据放在别处不受影响，
  但**不要把数据根目录设成默认目录里面的子目录**（设置页会警告）。
- 若把数据根目录设到可移动磁盘，拔盘后应用会起不来（日志会退回默认目录并记一条警告）。
- 老工程里以**绝对路径**记录过的临时图片（0.3.3 之前的格式）仍指向旧位置；
  切换后旧目录还在，这些图片照常能读，删掉旧目录后才会失效。

### 行为

1. `AppConfig`、`ProjectConfig` 的素材路径都从 `RuntimePaths` 推导（绝对路径，正斜杠，以 `/` 结尾）。
2. 数据库连接串由 `RuntimePathsEnvironmentPostProcessor` 注入为 `lbc.datasource.url`，
   供 `application.yml` 的 `spring.datasource.url: ${lbc.datasource.url}` 引用。
3. `ImageReader` 与资源加载逻辑优先按该绝对路径读文件系统，未命中再回退到类路径（`classpath:/assets/`）。

### 例子

在设置页切换（推荐）：设置 → 资源存储位置 → 更改位置… → 选 `D:\LBC-Data` → 复制现有数据 → 重启。

临时把数据根目录切到别处（开发/测试，不动安装版数据）：

```bash
# PowerShell
$env:LBC_DATA_DIR = "E:\lbc-test-data"

# 或 JVM 参数（jar 版本号见 demo\pom.xml，可用 node scripts\version.mjs 查看）
java -jar demo-0.2.3-SNAPSHOT.jar -Dlbc.data.dir=E:/lbc-test-data
```

在代码中读取：

```java
String bgDir = ProjectConfig.BACKGROUNDS_PATH; // 绝对路径，已归一化且以 '/' 结尾
Path assetsDir = RuntimePaths.getAssetsDir();
```

### 验证建议

- 修改配置后，运行后端编译并观察资源加载（或启动服务并访问资源 URL）。
- 若运行 Electron 前端，确保前端 `AppConfig`（前端配置）能正确指向后端 API 与资源前缀。
- `demo/src/main/resources/logback-spring.xml`: 后端日志主配置文件
- `demo/src/main/resources/logback.properties`: 后端日志属性配置文件
- `demo/frontend/electron-react-app/public/electron.js`: Electron 主进程配置（含前端日志配置）

## 注意事项

1. 修改配置后需要重启应用才能生效
2. 数据库配置变更可能需要手动迁移数据
3. 存储路径配置变更需要确保目录存在且有相应权限
4. 生产环境建议使用外部配置文件覆盖敏感信息
5. 日志文件会占用磁盘空间，建议定期清理或根据需要调整日志保留策略
6. 前端日志每次运行都会创建新文件，注意日志目录的磁盘空间管理
