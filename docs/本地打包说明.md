# 本地打包说明

日常本地出安装包，只要跑一个脚本：

```bat
E:\LimbusCompanyPlotVideoGenerator\demo\build-package.bat
```

双击运行，或在 cmd / PowerShell 里执行都可以（脚本自己会把 demo 当成工作目录，不用先 `cd`）。

## 产物在哪

| 内容 | 路径 |
|---|---|
| 安装包 | `E:\LimbusCompanyPlotVideoGenerator\release\LimbusCompany Plot Video Generator Setup 0.1.0.exe` |
| 增量更新校验文件 | `E:\LimbusCompanyPlotVideoGenerator\release\...exe.blockmap`、`latest.yml` |
| 免安装的解包目录（可直接跑） | `E:\LimbusCompanyPlotVideoGenerator\release\win-unpacked\` |
| 构建日志 | `E:\LimbusCompanyPlotVideoGenerator\demo\logs\build-<时间戳>.txt` |

产物目录由 `PACK_OUTPUT` 决定，脚本里已设为仓库根目录的 `release\`（绝对路径），并通过
`npx electron-builder … -c.directories.output="%PACK_OUTPUT%"` 传给 electron-builder。
想临时换位置，可以在调用前自己设：

```bat
set PACK_OUTPUT=D:/build-out
demo\build-package.bat
```

GitHub Actions 不经过这个脚本，`electron-builder.yml` 里的 `output: release` 保持默认，
产物仍落在 `demo/frontend/electron-react-app/release`，与 `.github/workflows/release.yml`
上传产物的路径一致 —— 改本地输出目录不影响 CI 发版。（如果以后让 CI 直接调用这个脚本，
要注意脚本会用 `-c.directories.output` 覆盖 yml 的输出目录，上传路径需要相应调整。）

## 脚本做哪四步

1. 用 jlink 生成内置 JRE（`demo\jre\`，已存在则跳过）
2. `mvn clean package -DskipTests` 打后端 jar（`demo\target\demo-1.0-SNAPSHOT.jar`）
3. `npm run build` 打前端（`demo\frontend\electron-react-app\build\`）
4. `npx electron-builder --win --x64` 出安装包（输出到上面的 `release\`）

打包前请**先关掉正在运行的程序**，并让编辑器放开对这个目录的占用，否则 `release\win-unpacked\resources\app.asar` 被占用会导致第 4 步失败（占用源与处理见下面注意事项）。

## 注意事项

- **安装目录名必须不带空格**：安装目录与可执行文件名由 `electron-builder.yml` 里的 `win.executableName` 决定（当前是 `LimbusCompanyPlotVideoGenerator`），不要为了"好看"把它改回带空格的 `productName`。安装路径带空格时，Spring Boot 3.2 生成的嵌套 jar URL（`jar:nested:/.../BOOT-INF/lib/xxx.jar!/...`）会把这个空格原样带进去，JavaCV/JavaCPP 解析该 URL 时抛 `URISyntaxException`，导致 FFmpeg 原生库加载失败（`UnsatisfiedLinkError`）；它是 `Error`，不会被 `catch (Exception)` 捕获，表现就是**安装版"导出视频"进度永远停在 0%**，且没有任何报错弹窗。本地 `mvn spring-boot:run` 用的是扁平 classpath，不会触发这个坑，所以本地永远看不出问题。`productName`（界面显示名、卸载项名称）、`nsis.shortcutName`、安装包文件名（`${productName} Setup x.x.x.exe`）都不受 `executableName` 影响，照旧即可。
- **装过带空格目录的旧版本，不建议"卸载再装"**：安装器会把上一次的安装目录写进注册表（`HKCU\Software\<APP_GUID>\InstallLocation`）并在升级时沿用，直接覆盖安装会装回原来带空格的目录，修复不生效；而卸载又会因为 `deleteAppDataOnUninstall: true` 删掉 `%APPDATA%\limbus-company-plot-video-generator`（项目数据库、assets、resources 都在里面，删了就没了）。推荐做法：运行新安装包，在"选择安装位置"页把路径改成不带空格的目录（例如 `...\Programs\LimbusCompanyPlotVideoGenerator`），装完再把旧的带空格目录手动删掉。另外要求整条安装路径都不带空格：如果 Windows 用户名本身带空格（例如 `C:\Users\John Doe`），`%LOCALAPPDATA%\Programs\...` 依旧带空格，这种情况只能靠把 Spring Boot 升到 ≥ 3.2.3 从根上解决。
- **需要管理员权限**：目前 `demo` 目录树里没有当前用户的权限条目（只有继承来的 Administrators/SYSTEM/Authenticated Users/Users），普通权限下脚本会卡在写 `demo\logs\build-*.txt` 并打印 `Access is denied.`，但外层仍显示 `BUILD SUCCEEDED`，很容易误判。所以请用**管理员身份**运行 cmd / PowerShell 再执行脚本。
- 想一次性修好权限，在管理员 PowerShell 里执行（把 `<你的用户名>` 换成实际账号）：
  ```powershell
  icacls "E:\LimbusCompanyPlotVideoGenerator" /grant "<你的用户名>:(OI)(CI)F" /T /C /Q
  ```
  之后再普通权限打包即可。
- 脚本只会停掉**仓库内**的残留进程（java/javaw/electron/app-builder/打包出的程序本身），不再像以前那样 `taskkill /im java.exe` 无差别杀掉机器上所有 Java 进程（那会顺带杀掉 VS Code 的 Java 语言服务器等无关程序）。构建期间如果控制台闪一下黑屏属正常现象。
- 脚本不会先删旧产物，而是把上一份 `PACK_OUTPUT` 改名成 `release.old` 再打包：**打包成功**才删掉它，**打包失败**（或目录被占用）时它原样保留，所以一次失败的构建不会把你的旧安装包弄没。只有目录名恰好是 `release` 时才会改名，把 `PACK_OUTPUT` 指到别的目录名（例如 `D:/build-out`）会跳过这一步、并在日志里给出 `[WARN]`。
- **目录被占用会直接失败退出**，不会再让 electron-builder 抛一堆 Go 堆栈，也不会删掉任何东西：日志里会写 `[ERROR] Cannot move ... aside - a file inside it is still locked by another process. Nothing was deleted`。日志里紧接着会提示占用源；也可以直接 `set PACK_OUTPUT=<另一个目录>` 再跑一次绕开它。
- **最常见的占用源是编辑器，不是程序本身**：2026-10-05 那次 `release\win-unpacked\resources\app.asar` 被占用，实测是 VS Code 的文件监视进程（`Code.exe --type=utility --utility-sub-type=node.mojom.NodeService`）一直握着这个 200+MB 的文件。已在 `.vscode\settings.json` 里把 `release`/`target`/`jre`/`node_modules` 加进 `files.watcherExclude` 与 `search.exclude`；如果改完设置仍被占用，**重载 VS Code 窗口**（`Ctrl+Shift+P` → `Developer: Reload Window`）或直接关掉 VS Code 再打包。想确认到底是谁占着，用「资源监视器」→ CPU → 关联的句柄里搜 `app.asar`。
- 非 CI 模式下脚本只在最外层暂停一次（内层的输出被重定向进日志，所以内层不暂停）；以前那种“构建完成后控制台卡住、要盲按一下键”的现象已修掉。
- 想让脚本按 CI 模式跑（不暂停、打包带 `--publish never`），设 `CI=true` 或 `CI=1`；设成 `CI=false` 不会进入 CI 模式。
- **脚本必须保持纯 ASCII（注释写英文）**：内层会执行 `chcp 65001`，此时 cmd 解析多字节（中文）注释会错位，把注释行的后半截当成命令执行，日志里就会出现 `'xxx' is not recognized as an internal or external command`。中文说明一律写在本文档里，不要写进 `.bat`。
- 另外修掉了一个会让“打包成功也报失败”的坑：旧版失败分支写成 `if errorlevel 1 ( ... echo ... (try rebooting) ... goto :FATAL )`，echo 文本里的 `)` 会被 cmd 当成括号块结束，导致 if 体提前结束、后面的 `goto :FATAL` 无条件执行。现在改成 `if not errorlevel 1 goto :PACK_OK` 分流。

## 打完包怎么验

1. 直接跑 `release\win-unpacked\LimbusCompanyPlotVideoGenerator.exe`（免安装，快速试）
2. 或把 `release\...Setup.0.1.0.exe` 发给别人覆盖安装
3. 打开程序后进"剧情编辑"，预览图正常显示即 OK；若报错，预览区会直接写出 HTTP 状态、服务端消息和缺失的素材文件

相关文件：`demo\build-package.bat`、`demo\frontend\electron-react-app\electron-builder.yml`
