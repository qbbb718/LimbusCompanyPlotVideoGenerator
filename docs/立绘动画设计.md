## 0. 已冻结的决策（不可再改，改要重新评审）

| 域 | 决策 |
|---|---|
| 技术路线 | **纯函数求值内核**（前端 TS + 后端 Java 各一份，靠共享夹具对拍）。**不引入** GSAP / Framer Motion / Lottie / WAAPI / CSS keyframes 做内容动画 |
| 求值位置 | **世界坐标、元素局部**，在 camera 投影**之前**（自动继承 plot 的 0.8 场景缩放与输出分辨率无关） |
| 时间单位 | **帧**（整数），`timebase.fps = 30` 仅作**契约断言**；非 30 时两端都告警，不静默换算 |
| 合成方式 | **通道级**：`x/y/rotate` 加法、`scale/alpha` 乘法、`replace` 显式覆盖。默认组合**可交换** |
| 时长公式 | `D = max(文字, 音频, 动画) + stayFrames`；动画项**必须带 `plot` 门禁** |
| 时长参与 | 有限 clip 参与；**无限循环不参与**；显式 `endFrame` 不参与；情绪 sprite 的 `once/hold` 参与、`loop` 不参与；单条 ≤ 300 帧 |
| 停留帧数 | **工程级**，随工程文件保存 + 随导出请求传参；**禁止**改 `ProjectConfig` 的 static 字段 |
| 缓存 | 片段文件名带**时长指纹** `fp8 = hash(stayFrames, fps, plot, width, height)` |
| 中断语义 | `endFrame` + `onEnd` + `fadeIn/fadeOut` **权重包络**；**不做** clip 间 crossfade |
| 作用对象 | 立绘 **和** 临时图片 |
| 编辑形态 | 预设 + 参数表单 + **关键帧时间轴**（点轴跳帧、菱形选中、检查器改值）；不做曲线编辑器 |
| 预设复用 | 三层：L1 程序化 / L2 内置 JSON（开发者丢文件即生效）/ L3 用户自存；**套用 = 内联快照 + `sourcePresetId`**；**禁止**预设嵌套预设 |
| 预设参数 | 只支持**数字**占位符 `${name}`，不做表达式引擎 |
| 抖动随机 | `seed` **入库**；**整数 hash**（禁浮点） |
| 环境 | 仅 Windows 桌面 Electron；**无移动端/多浏览器**要求 |
| 渲染优化 | 静态层**三段切分**（base / dynamic band / overlay）；`dim` 压暗**必须缓存** |

## 1. 术语与坐标系（这一节搞错，后面全错）

### 1.1 现有坐标链

```
CharacterVisual.updatePos()      世界坐标 rect（posX/posY + 裁剪框推导的缩放）
        │  ← 本方案的动画变换插在【这里】（元素局部、世界空间）
        ▼
Camera.screenX/screenY/screenScale    世界 → 场景画布 1920×1080
        ▼
PLOT_SCENE_SCALE = 0.8 + 偏移 (192,108)   场景 → 设计画布
        ▼
composeFinalImage 按输出分辨率缩放        设计画布 → 成片帧
```

**为什么插在这一层**（三条理由，不要改动位置）：
1. `plot` 的 0.8 与偏移在下游，**自动继承**，不需要手算；
2. 与 camera 正交：先动元素、再取景；
3. 世界像素与分辨率无关，1080p / 720p / 4K 构图一致。

### 1.2 变换定义

元素世界矩形 `R`（左上角 `L`、尺寸 `W×H`），锚点 `A = L + (ax·W, ay·H)`。
动画给出 `T = {x, y, scale, rotate, alpha}`，世界内任意点：

```
p' = A + R(θ)·S(s)·(p − A) + d        d = (dx, dy)，单位 = 世界像素
```

- `x/y` 是**相对静态姿态的增量**，**不覆盖**用户拖出来的位置；
- `rotate` 单位度、顺时针为正（CSS 与 Java2D 同号，无需翻转）；
- `alpha` 是乘子（1 = 不透明）。

## 2. 数据模型（已冻结，`version: 1`）

### 2.1 类型

```ts
/** 挂在 CharacterVisual / TempImageVisual 上的动画装备 */
interface SpriteAnimation {
  version: 1;
  timebase: { unit: "frame"; fps: 30 };   // 契约断言
  enabled?: boolean;                       // 缺省 true
  anchor?: { x: number; y: number };       // 0~1；缺省立绘 (0.5,1)、图片 (0.5,0.5)
  clips: AnimationClip[];                  // 顺序 = 叠加顺序（仅在 replace 时有意义）
}

type LoopMode = "once" | "loop" | "pingpong" | "hold";
type BlendMode = "add" | "mul" | "replace";
type AnimChannel = "x" | "y" | "scale" | "rotate" | "alpha";

interface AnimationClip {
  id: string;                 // 稳定 id（编辑器选中/删除/undo）
  kind: "preset" | "keyframes";
  enabled?: boolean;

  /* 时间（全部单位 = 帧） */
  startFrame?: number;        // 缺省 0
  endFrame?: number;          // 缺省 null = 跟记录结束；显式值**不参与**时长计算
  durationFrames: number;
  loop?: LoopMode;            // 缺省 "once"
  iterations?: number;        // 缺省无限（仅 loop/pingpong 有意义）
  timeScale?: number;         // 速度倍率，**影响成片**

  /* 预设 */
  preset?: PresetId;
  params?: Record<string, number | string | boolean>;

  /* 关键帧 */
  channels?: AnimChannel[];
  keys?: Keyframe[];
  blend?: BlendMode;
  priority?: number;

  /* 过渡包络 */
  fadeInFrames?: number;      // 缺省 0
  fadeOutFrames?: number;     // 缺省 0（loop 模式必须为 0）
  onEnd?: "reset" | "hold";   // 缺省 "reset"

  /* 预设来源（套用时由系统写入，只读展示用） */
  sourcePresetId?: string;
  sourcePresetVersion?: number;
}

interface Keyframe {
  f: number;                  // 相对 clip 起点，整数 ≥ 0
  v: Partial<TransformState>; // 只写变化的通道
  ease?: "linear" | "easeIn" | "easeOut" | "easeInOut" | "step";  // 缺省 linear
  hold?: boolean;             // = step
}

interface TransformState { x: number; y: number; scale: number; rotate: number; alpha: number; }
```

### 2.3 兼容与归一化

- `CharacterVisual` / `TempImageVisual` 都是 `@JsonIgnoreProperties(ignoreUnknown = true)`；老工程无 `anim` → **恒等变换** → 导出**逐像素不变**（这是回归基线）。

## 3. 求值算法（双端必须逐位一致）

### 3.1 时间投影

```
project(clip, frame):
    if !clip.enabled:                        return null
    if frame < (clip.startFrame ?? 0):        return null
    t = (frame - startFrame) * (clip.timeScale ?? 1)      // 小数允许
    len = clip.durationFrames
    if len <= 0:                             return null

    // 有限结束
    if endFrame != null && frame >= endFrame: return null

    switch (loop ?? "once"):
      once:     if t >= len: return null（由 onEnd 决定收尾，见 3.5）
                return t
      hold:     return min(t, len - 1)
      loop:     return t % len
      pingpong: m = t % (2*len); return m <= len ? m : 2*len - m
```

> `endFrame` 缺省 = `null` = "跟记录结束" —— **不要**把记录时长写进数据，否则与 §4.6 形成循环依赖。

### 3.2 预设公式（`local` 为投影后的帧；`u = local / durationFrames`）

| 预设 | 参数（默认） | 公式 | 通道 |
|---|---|---|---|
| `bounce` | `amplitude` 24px、`periodFrames` 18、`iterations` 2、`decay` 0.55 | `k = floor(local/T)`；`s = local % T`；`k >= iterations` → 0；`y = −A·sin(π·s/T)·decay^k` | y（可选 scale 挤压） |
| `shake` | `amplitude` 6px、`periodFrames` 2、`style` "jitter"、`seed`、`axes` "xy" | **jitter**：`i = floor(local/T)`；`w = (local%T)/T`；`nx = hash01(seed,i,0)`；`x = A·lerp(2·h01(seed,i−1,0)−1, 2·nx−1, w)`；y 同理换通道号<br>**sine**：`x = A·sin(2π·local/T)` | x,y（可选 rotate） |
| `breathe` | `amplitude` 0.025、`periodFrames` 120 | `scale = 1 + A·sin(2π·local/T)` | scale |
| `sway` | `angle` 2.5°、`periodFrames` 90 | `rotate = A·sin(2π·local/T)` | rotate |
| `blink` | `min` 0.35、`periodFrames` 24、`duty` 0.5 | `phase = (local % T)/T`；`e = min(2/T, duty/2)`；`w = clamp01(phase/e)·clamp01((duty−phase)/e)`；`alpha = 1 + (min−1)·w` | alpha |
| `pulse` | `peak` 1.12、`periodFrames` 18 | `q = clamp01(local/T)`；`scale = 1 + (peak−1)·sin(π·q)` | scale |

所有预设 `t = 0` 时必须为**恒等值**（`x=y=rotate=0, scale=alpha=1`），否则一加动画就会跳一下。

### 3.3 关键帧插值

```
seg = 找到 f_i <= local < f_{i+1}
e   = keys[i].hold ? "step" : (keys[i].ease ?? "linear")
p   = ease((local - f_i) / (f_{i+1} - f_i), e)
v[ch] = v_i[ch] + (v_{i+1}[ch] - v_i[ch]) * p       // 每通道独立线性 + 共用缓动
// 越界：local < keys[0].f → 取 keys[0]；local >= last.f → 取 last
// 缺省通道：沿用上一关键帧的该通道值（首帧缺省 = 恒等）
```

缓动只允许 `linear / easeIn / easeOut / easeInOut / step`（与 `cameraView.easeProgress` 同一组公式，见该文件注释）。**要 cubic-bezier 时不要两端各写一遍 Newton 迭代**，改用"共享采样表"。

### 3.4 通道合成

```
T = { x:0, y:0, scale:1, rotate:0, alpha:1 }
for clip in clips（按数组顺序）:
    local = project(clip, frame);  if null: continue
    c = preset(clip) | keyframes(clip)
    w = envelope(clip, local)                       // 见 3.5
    for ch in channelsOf(clip):
        mode = clip.blend ?? defaultBlend(ch)       // add: x,y,rotate / mul: scale,alpha
        T[ch] = compose(mode, T[ch], c[ch], w)
```

| mode | 合成 |
|---|---|
| `add` | `T + c·w` |
| `mul` | `T · (1 + (c − 1)·w)` |
| `replace` | `T + (c − T)·w`（`priority` 高者先；同级按数组顺序靠后者覆盖） |

> 默认 add/mul 满足交换律 → 用户不必关心 clip 顺序。**顺序只影响 `replace`**。

### 3.5 权重包络（解决"硬跳"）

```
w = clamp01(local / max(1, fadeInFrames)) · clamp01((len − local) / max(1, fadeOutFrames))
// fadeIn = fadeOut = 0 时 w ≡ 1（除零保护先判 0）
```

- `loop` / `pingpong` 的 `fadeOutFrames` **必须为 0**，否则循环接缝会闪；
- `once` + `onEnd: "reset"` 时，编辑器套预设**自动给 `fadeOutFrames = 6`**（可改）。

### 3.6 确定性 hash（抖动）

```java
// 两端必须逐位一致
int fmix32(int h) {
    h ^= h >>> 16; h *= 0x85ebca6b; h ^= h >>> 13;
    h *= 0xc2b2ae35; h ^= h >>> 16; return h;
}
int bits = fmix32(Math.imul(i, 374761393) + Math.imul(seed, 668265263) + axis);
double u = (bits >>> 0) / 4294967296.0;      // [0,1)
```

- JS 必须用 `Math.imul`（`*` 会退化成浮点）；Java 用 `int` 天然补码。
- **禁止**任何浮点参与的 hash（`Math.sin(seed)` 之类两端最后一位会不一致）。

### 3.7 单端点（两端各自实现，签名一致）

```
evaluate(anim: SpriteAnimation | null, frame: int) -> TransformState
```

- **纯函数**：不读时间、不读 RNG、不读 devicePixelRatio、无副作用；
- 无 `anim` / `!enabled` → 返回恒等；
- 恒等判断容差：`|x|,|y| < 0.01`、`|scale−1| < 1e-4`、`|rotate| < 1e-4`、`|alpha−1| < 1e-4`。

### 4.3 单角色绘制（`RenderOfImage.renderSingleCharacter`）

```java
TransformState t = SpriteAnimator.evaluate(chara.getAnimation(), frameIndex);

// 1) 先算基础绘制参数（含 camera）
float s = chara.getRenderScale(); int x = chara.getPosX(), y = chara.getPosY();
if (camera != null && !camera.isIdentity()) { s = camera.screenScale(s); x = camera.screenX(x); y = camera.screenY(y); }

// 2) 再叠加动画：绕 anchor 的仿射，**一次性复合**（禁止逐点换算后再 g.rotate）
Point2D A = anchorInScreen(chara, camera);          // 锚点在场景画布里的坐标
AffineTransform M = new AffineTransform();
M.translate(A.x + t.x*zoom, A.y + t.y*zoom);
M.rotate(Math.toRadians(t.rotate));
M.scale(t.scale, t.scale);
M.translate(-A.x, -A.y);
M.translate(x, y); M.scale(s, s);                    // 落回"画原图"的变换
composer.addImageLayerAffine(image, M, t.alpha);
```

- 图片取 `dim ? DimCache.of(image) : image`（见 4.5）；
- 无动画（恒等）时**必须走原路径** `addImageLayerScaled(...)`，保证逐像素不变。

### 4.4 三段切分（`RenderOfVideo.exportRecordVideoStreaming`）

图层序列：`背景 → 立绘（逆序） → 临时图片 → 边框遮罩`。按"是否有动画"切成三段：

```
base         = 最靠前的动画元素之前的所有层      → 整段渲 1 次
dynamic band = 动画元素 + 夹在其间的层           → 每帧重画（仅这几层）
overlay      = 最靠后的动画元素之后的所有层      → 整段渲 1 次
帧 = copy(base) → 画 dynamic band（带变换） → 叠 overlay → 台词 → 转场
```

- **camera 也在动时**（`cameraAnimated`）→ 直接退化为整层逐帧重渲（沿用现有分支，不叠加优化）；
- **无任何动画** → 完全不进新分支，保留现有"定格复用"，**导出耗时与像素都不变**。

### 4.5 `dim` 缓存（必须做）

`renderSingleCharacter` 现在每调一次就 `ImageDarkener.darkenImage(image, 0.5f)`。逐帧重画会变成**每帧一次全图遍历 + 新图分配**。
→ `common/util/DimCache.java`：`WeakHashMap<BufferedImage, BufferedImage>`，key 用图像身份（`IdentityHashMap` 语义）+ 固定比例 0.5。

### 4.6 时长公式（`RecordDurationCalculator`）

```java
// 保持无 IO！素材帧数由上层解析后注入
public static int calculateDurationFrames(Record record, int frameRate, int stayFrames,
                                          AnimationDurationInfo info) {
    int audio = calculateAudioDuration(record, frameRate);
    int text  = calculateTextDuration(record, frameRate);
    int anim  = info == null ? 0 : info.maxFrames();
    return Math.max(Math.max(audio, text), anim) + stayFrames;
}
```

`calculateAnimationDuration`（在 info 的构建处）：

```
A = 0
for visual in (plot ? record.chars : []) :            // ← plot 门禁（plot=false 立绘不渲染）
    if visual.portrait == null: continue               // ← 立绘缺失也不可见
    A = max(A, sumOfFiniteClips(visual.anim))
for visual in record.tempImages :                      // ← 临时图片不受 plot 影响
    A = max(A, sumOfFiniteClips(visual.anim))
for sprite in 情绪 sprite 列表 :                        // ← 见 §7
    if sprite.parent == portrait && !plot: continue
    if sprite.playback == loop: continue               // 无限不参与
    A = max(A, min(300, sprite.delayFrames + frameCount))
```

`sumOfFiniteClips(clip)`：`once/hold` → `start + duration`；`loop/pingpong` 且有 `iterations` → `start + duration*iterations`；无限循环或显式 `endFrame` → **不参与**。

**必须同步的 3 处调用点**（只允许一个 public 出口，其余 private）：
`RenderOfVideo`（`requiredFrames`）、`BatchVideoProcessor`（缓存复用分支 + 另一处）。任一处算错 → 音画不同步。

### 4.7 缓存指纹

```
片段文件名：record_{uuid}_{fp8}.{ext}
fp8 = hash32(stayFrames, frameRate, plot, width, height).toHex().substring(0,8)
复用条件不变：文件存在 && !record.isDirty() && !交叉溶解
```

**不要**用"目录级单一 manifest"（工程切换时会来回全量失效）。指纹进文件名可天然避免跨工程误用，也顺手修掉"切换剧情类型仍复用旧片段"的既有隐患。

### 4.8 工程文件格式（承载 `stayFrames`）

现状：`serializeProject(records, groups)` 只产出**顶层数组**，没有任何 settings。改为：

```jsonc
{ "version": 1, "settings": { "stayFrames": 75 }, "records": [ ... ] }
```

- `parseProjectText` 已兼容"数组 / `{records}`"两种形状 → 只需再读 `settings`；
- **旧版本软件打开新工程**：命中 `Array.isArray(data?.records)` 分支 → 记录完好，仅丢 `stayFrames`（回落 75）；
- **动手前必查**：全局搜"谁还直接读这个工程文件"（后端 `RecordsIO` 是顶层数组格式）。查到就给它加兼容（顶层是对象则取 `records`），**不要假设没有**。
- `stayFrames` **随导出请求传参**，**禁止**写成 `ProjectConfig.DEFAULT_STAY_FRAMES` 的运行时 set（会把并发导出任务互相污染）。

### 4.9 导出参数重构

`RecordEditor` 现在这样调：`generateVideo(records, outputPath, w, h, 30, layerTypes, keepTempFiles, projectName, plot)`（9 个位置参数）。加 `stayFrames`、`animationsEnabled` 前**先收成 `VideoExportOptions` 对象**。

### 4.10 灰度开关

请求参数 `animationsEnabled`（缺省 true）。置 false 时全域按恒等处理，**与改动前逐像素一致**。发布后出问题一条开关回退，不靠回滚发版。

## 5. 前端实现（S3 / S4）

### 5.1 模块划分（`src/features/record/animation/`）

`animationTypes.ts`、`channels.ts`、`easings.ts`、`spriteAnimator.ts`、`presetRegistry.tsx`、`keyframeEngine.ts`、`useTimelinePlayback.ts`；UI：`AnimationListPanel.tsx`、`PresetPickerModal.tsx`、`PresetParamsForm.tsx`、`KeyframeTable.tsx`、`AnimationTransport.tsx`。

### 5.2 DOM 变换规则（**这一节最容易做错**）

```ts
txPct = (t.x / layer.baseRect.w) * 100;     // 相机 / 0.8 / 分辨率全部抵消，见推导
tyPct = (t.y / layer.baseRect.h) * 100;

style.transform = `translate(${txPct}%, ${tyPct}%) rotate(${t.rotate}deg) scale(${t.scale})`;
style.transformOrigin = `${anchorX * 100}% ${anchorY * 100}%`;
style.opacity = t.alpha;
```

- **顺序必须是 `translate → rotate → scale`**（CSS 从右往左作用 = 先缩放/旋转、后平移，与 §1.2 的公式等价）；
- `translate` 的百分比基准是元素**未变换的 border-box**，所以旋转不会污染平移基准；
- `left/top/width/height` **保持不动**（不动 layout）；
- 推导：`outRect.w = baseRect.w · zoom · 0.8 · kx`，故 `t.x·zoom·0.8·kx / outRect.w = t.x / baseRect.w`。

### 5.3 几何钩子

`buildPreviewGeometry` 增加可选 `animAt(layerKey, frame) → TransformState`，在 `space === "world"` 的 layer 上、`baseRect` 之后、`worldToScene` 之前应用。
`PreviewSceneLayer` 的 `SceneLayerItem` 增加三个可选字段：`transform`、`transformOrigin`、`playing`。

### 5.4 播放控制器

新增 `useTimelinePlayback(totalFrames = D)`：`play / pause / stop / seek(frame) / previewSpeed / loop`，rAF 帧驱动（沿用 `useCameraPlayback` 的写法），**镜头与立绘共用同一个播放头**。
播放中：栅格图 `opacity: 0`、DOM 场景层顶上（复用 `RecordPreview` 现有分支）。
`will-change: transform` **只在播放中挂**，停止立即移除（否则每个立绘一层显存纹理）。

### 5.5 UI 要点

- 入口：`CharactersProperties` 与 `TempImagesProperties` 的角色卡片里加「动画」折叠区；
- 预设参数表单由 `params` 元数据**自动生成**（滑杆 + 数值框，复用 `NumberField` 风格）；
- 关键帧**时间轴**：横轴 = clip 的 local 帧区间，菱形 = 关键帧，播放头 = 预览当前帧；
  点轴/点菱形都把预览跳到那一帧；选中后在检查器里改 `帧 | x | y | scale | rotate | alpha | 缓动 | 删除`，支持在播放头处插帧；
  **未做**：拖动菱形改帧号、上下移、吸附整数帧（拖动合并 undo 一起留到 S4③）；
- 播放条：`▶ 播放整条记录 / ⏸ / ⏮ / 帧 N / D / 速度 / 🔁`；
- **拖动期间合并为一条 undo**（沿用现有拖拽 merge 策略，别一次拖动产生几十条历史）；
- `plot === false` 时：立绘页签的动画区 **`disabled` + 一行提示**（"当前剧情类型为『人格故事』，立绘不参与渲染 —— 这些动画不会出现在成片里"）。**不要**隐藏整个页签；**不要**对临时图片做同样的灰显。
- 结尾停留时长：加在「全局设置」tab（`GlobalProperties`），文案标明**"随本工程保存"**，设置页**不加**入口。

## 7. 父子 sprite 契约（S6，依赖"情绪动画"线）

**本文只负责契约**，情绪 sprite 功能本身在 `docs/情绪动画设计.md` 那条线里实现。

- 情绪 sprite 是**立绘的子级**：锚点与尺寸表达在**立绘局部空间**，由父级变换统一映射；
- 继承模式：`rigid`（默认，位移 + 旋转，**不继承 scale**）/ `full`（全仿射）；
- 绘制位置：`renderCharacters` 循环内、**紧跟父立绘之后** → 自动获得 camera / 0.8 场景缩放 / 边框暗角 / 场景裁剪（**旧文档里手算 0.8 的写法整段删除**）；
- 概念切分：`parent: "portrait"`（附着特效，跟随）vs `"record"`（全屏特效，不跟随）；
- 前端：sprite canvas 与立绘 `<img>` 用**同一个** `transform` 字符串，但 `transform-origin` 必须换成"**同一个绝对点 A 在各自元素盒子里的百分比**"：

```
子级 origin = (A.x − Rs.x)/Rs.w, (A.y − Rs.y)/Rs.h        // 允许 <0 或 >100%
```

> 直接抄父级的 origin 百分比 → 旋转/缩放绕错支点，表现为"立绘在抖、汗滴绕着画面中心甩出去"。

## 10. 陷阱清单（每条都真的会踩）

1. **camera 与动画的复合顺序**：先 `screenX/screenY` 再 `g.rotate()` → 变成"绕画布原点旋转"。必须把"世界→场景"的缩放平移与动画的旋转缩放**并进同一个 `AffineTransform`**，一次性交给 `drawImage`。
2. **前端父子 `transform-origin`**（§7）：抄父级百分比 → 子级绕错支点。写专测：`rotate=30° + 子元素在父元素右外侧`。
3. **时长公式三个出口**：只要有一处自己算，就会出现"预览说 315 帧、成片 240 帧"。只允许一个 `public` 入口。
4. **`dim` 每帧重算**：逐帧重画时不缓存压暗结果 → 每帧一次全图遍历（§4.5）。
5. **`static` 被并发污染**：`ProjectConfig.DEFAULT_STAY_FRAMES` 是 `public static int`，导出又是异步队列 → 改成运行时 set 会互相覆盖。
6. **无限循环拉长记录**：一个"呼吸循环"让每条记录都变长（§4.6 的参与规则）。
7. **`t = 0` 不为恒等**：预设首帧非恒等 → 一加动画画面就跳一下。
8. **`loop` 模式给了 `fadeOutFrames`**：循环接缝会一淡一显。

## 11. 禁止事项（Don't）

- ❌ 用 CSS keyframes / WAAPI / GSAP / Framer Motion / Lottie 实现**内容动画**（它们进不了 Java 成片，必然双份实现漂移）。这些只允许用于应用外壳的 UI 装饰（如现有 spinner）。
- ❌ 把动画烘焙进预览 PNG（预览缓存键会变，且每帧只能看一张）。
- ❌ 在 `endFrame` 缺省值里写"记录时长"（与时长公式形成循环依赖）。
- ❌ 为了"可配置"去 set `ProjectConfig` 的 static 字段。
- ❌ 做 clip 间 crossfade / 混合树（要连续过渡 → 用关键帧时间轴）。
- ❌ 用浮点参与 hash（`Math.sin(seed)` 之类）。
- ❌ 把父子 sprite 画到 UI 之上（要吃父子变换就必须在场景层内）。
- ❌ 对 `plot=false` 的立绘动画"偷偷隐藏整个页签"（用户会以为数据丢了）。
- ❌ 为 sprite 被裁剪/被暗角压暗而加特例（那是**正确**行为）。

### C.2 与正文的偏差（**已按实现为准**）

1. **弹跳没有"压扁（squash）"，改成"拉伸（stretch）"**。
   压扁在 `local = 0`（落地帧）就产生非恒等缩放，违反"加动画不能跳一下"的硬约束；
   改成 `scale = 1 + stretch·|sin|` 后 `t=0` 恒等，顶点略微拉长，观感同样成立。参数名 `stretch`，默认 0。

2. **缓存指纹用旁文件 `xxx.mp4.fp`，不改片段文件名**。
   正文 §9 建议把 `fp8` 拼进文件名，但 `generateVideoFileName` 有 5 个调用点（含异步路径与日志），
   改名会牵动所有"按名字找片段"的代码。旁文件等价且局部：只有 `canReuseRenderedClip` 与两处渲染后写盘需要改。
   **安全方向**：指纹缺失视为不一致（升级后首次导出一律重渲一次并补写）。

3. **`RecordAnimation` 放在 `render.engine`，不放 `anim` 包**。
   `anim` 包必须保持"只认 `SpriteAnimation`、不认 `Record`"的纯数学身份（这是它能双端对拍的前提）。

4. **三段切分（base / dynamic band / overlay）暂未实现**，改为「逐帧重渲 + 动画签名复用」。
   正确性优先：先让"每帧按当帧变换重渲整个场景"跑通（与镜头动画同一条路径）；
   性能靠 `RecordAnimation.sceneSignature` 兜底——弹跳弹够次数后、`once` 结束后的尾巴帧签名不变，
   直接复用上一帧的场景层，不再重画。若后续实测仍偏慢，再按 §4.4 上三段切分。

5. **新增了 `SpriteImageCache`（预缩放 + 压暗缓存）**，正文只提了 dim 缓存。
   逐帧重画时 `scaleImageHighQuality` 与 `ImageDarkener.darkenImage` 都是每帧一次的整图运算，
   必须缓存；弱引用键 + 每图最多 8 档 LRU。

6. **"无动画空台词记录"的时长基线是 78 帧，不是 75**。
   `Dialogue` 会把空文本替换成 `DEFAULT_TEXT = "..."`（3 字符）→ 文字时长 3 帧。
   写时长测试时必须以 `3 + DEFAULT_STAY_FRAMES` 为基线（`RecordDurationCalculatorAnimationTest.LEGACY_BASELINE`）。

7. **`calculateDurationFrames(record, frameRate)` 两参重载仍在**（默认 `plot = true`，仅为兼容旧调用）。
   新代码一律显式传 `plot`；否则人格故事模式会出现"动画看不见但记录变长"的幽灵时长。

### C.5 截帧验收（已自动化）怎么跑

```powershell
powershell -NoProfile -File scripts\animation-acceptance\run.ps1
```

三步，全在 `scripts/animation-acceptance/` 里：

1. `AnimationFrameAcceptanceExport`（`demo/src/test/java/...`，默认 `@EnabledIfSystemProperty` 不跑）：
   用**和 `PortraitAnimationVideoTest` 同一个记录**（立绘 + 弹跳 + 摇摆）真的导一条 mp4，再用项目自带
   ffmpeg 解帧 —— 验收对象是"用户拿到的那条成片"，不是内部中间态。同时吐 `manifest.json`
   （立绘在输出图上的未变换矩形、世界矩形、锚点、动画 JSON）和 `probe.png`。
2. `run.ps1` 用 tsc 把 `src/features/record/preview/domTransform.ts` 与
   `src/features/record/animation/spriteAnimator.ts`（**编辑器里同一份源码**）编译成 CommonJS。
3. `capture.js`：离屏 Electron（`nodeIntegration`）里加载 `previewStage.html`，按 `PreviewSceneLayer`
   的百分比规则摆 `<img>`，`transform` 用 `spriteDomStyle` 算，截图后与成片帧比 ROI 内**强度加权质心**。

**通过标准**：每帧绝对位置差 ≤ 2px；帧 9 相对帧 0 的位移差 ≤ 1px（等于在验"位移量 + 绕脚底旋转"）。
证据目录 `demo/target/animation-acceptance/`（`backend/frame-*.png` + `preview-frame-*.png`）。

**它覆盖什么**：Java2D 仿射与浏览器 CSS `transform` 的光栅化落点是否一致（含 `transform-origin`
百分比、`translate→rotate→scale` 顺序、百分比位移的取整）；
**它不覆盖什么**：`RecordPreview` 的 React 接线（由 `domTransform.test.ts` + `previewLayout.test.ts` 覆盖）、
`camera.zoom ≠ 1` 时预览侧的复合（预览按"元素盒子百分比"表达位移，与 zoom 无关是构造性的；
后端 zoom≠1 的换算由 `PortraitAnimationRenderingTest` 的 40px/80px 断言覆盖）、
`clip-path` 裁剪与 `dim` 压暗（视觉上没风险，且不影响落点）。
失败时按 §10 前三条查：camera × 动画复合顺序 → 父子 `transform-origin` → 百分比取整精度。
