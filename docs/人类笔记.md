
## 打包分发

### Github Action打包


顺序固定为：**① 改版本号 → ② commit + push main → ③ 有旧 tag 先删 → ④ 打 tag 并核对它指的 commit → ⑤ push tag**。

#### 1. 改版本号（只动源码，不碰 tag）

```powershell
# 查看当前版本、以及各处版本号是否一致
node scripts\version.mjs
# 改成 0.3.4（不带 --write 只是干跑，打印会改哪些行）
node scripts\version.mjs 0.3.4 --write
# 只校验不改（CI 用的就是这个）：比对各处是否一致
node scripts\version.mjs --check
# 版本工具自测（改过 scripts\version.mjs 后跑一次）
node scripts\version.test.mjs
```

顺手在 [版本更新笔记](版本更新笔记.md) 顶部加一节 `## 0.3.4`，那是发版说明的来源。

#### 2. 提交，tag 必须打在这笔提交上

```powershell
git add -A
git commit -m "0.3.4"
git push origin main
```

工作区有未提交的改动时 `git tag` 照样能成功，但 tag 里不含那些改动 —— 所以必须先 commit。

#### 3. 同名 tag 先删干净（重复发版时最容易踩的坑）

`git tag v0.3.4` 遇到同名 tag 会 `fatal: tag 'v0.3.4' already exists` 直接失败，
而紧接着的 `git push` 不会因此停下：推上去的还是**旧 tag → 旧 commit（旧版本号）**，
CI 就停在开头那串 `[FAIL]` 上。所以先查、先删：

```powershell
git tag --list v0.3.4             # 有输出说明本地已有，需要删
git tag -d v0.3.4                 # 删本地 tag
git push origin :refs/tags/v0.3.4 # 删远端 tag（GitHub Releases 里那次失败的 release 一并删掉）
```

#### 4. 打 tag，并核对它指的 commit

```powershell
git tag v0.3.4
git rev-parse HEAD               # 当前提交
git rev-list -n 1 v0.3.4         # tag 指向的提交：必须与上一行完全一致
# 再从 tag 内容里读一次版本号：必须是 0.3.4，这一步最能提前发现「tag 打早了」
git show v0.3.4:demo/frontend/electron-react-app/package.json | Select-String '"version"'
# CI 的那条校验命令，本地也能跑
node scripts\version.mjs --check-tag v0.3.4
```

> 注意 `--check-tag` 比的是**工作区里的文件** + 「git 里有这个 tag」，它不读 tag 里的内容，
> 所以 tag 打早了它照样打印 `OK`（工作区是 0.3.4，tag 也真的存在）。能抓住「tag 打早了」的
> 只有上面那两行哈希对比（`rev-parse HEAD` vs `rev-list -n 1 v0.3.4`）和
> `git show v0.3.4:<路径>`——本地全绿、CI 却报 `version: 0.3.3`，就是这种情况。

#### 5. 推送

```powershell
git push origin main v0.3.4
```

只有推 tag 才触发 CI，只推 `main` 不会发版。跑完 GitHub Releases 里会有
`LimbusCompany Plot Video Generator Setup 0.3.4.exe`、`*.blockmap` 和 `latest.yml`（自动更新用）。

#### tag 已经推到旧 commit 了怎么救

不用重做版本号，把 tag 挪到正确提交上、强推覆盖远端即可，CI 会重新跑一次：

```powershell
git tag -f v0.3.4 HEAD           # 或 git tag -f v0.3.4 <正确的 commit>
git push origin v0.3.4 --force   # 覆盖远端同名 tag；只影响这个 tag，不动 main
```

#### 常见报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `version: 0.3.3 (expected 0.3.4)` + 一串 `[FAIL]` | tag 指到改版本号之前的 commit | 按上一条把 tag 挪到正确提交并强推 |
| `fatal: tag 'v0.3.4' already exists` | 本地已有同名 tag，这次 `git tag` 没生效 | 先 `git tag -d` + 删远端 tag，再重打 |
| `[rejected] v0.3.4 ... (already exists)` | 远端已有同名 tag 且指向别的 commit | 确认要覆盖：`git push origin v0.3.4 --force` |
| `git tag v0.3.4 does not exist` | 只推了 `main`，tag 没推 | `git push origin v0.3.4` |
| 本地 `--check` 通过但 CI 失败 | 版本号改动没 commit，或 commit 了没推 `main` | 先 commit + `git push origin main` |

（`workflow_dispatch` 手动 Run workflow 只把校验换成 `--check`，后面的构建和 `--publish always`
照旧执行，所以「只想验版本号」还是在本地跑 `node scripts\version.mjs --check` 更快。）
