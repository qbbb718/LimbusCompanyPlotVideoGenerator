
## 0.2.4

- 修复安装版「立绘显示为红色『加载失败』方块」的问题。日志里只有一句
- 新增安装包自检：`java -jar demo-<版本>-SNAPSHOT.jar --self-check=webp`
- 立绘读不出来时的报错不再是一句"读不出来"：`ImageReader` 会带上具体失败原因
  （原生库不可用 / 文件损坏 / 路径不存在），日志里也能直接搜到。
- 版本号现在会显示在界面上与日志里（同一真源，界面/日志都没有硬编码版本号）
- 修复立绘身高计算错误
- 立绘 WebP 改为**入库时转成 PNG 存盘**，原图备份到角色目录下的 `originals/`：解码只在上传时发生一次，
  解不出来就当场拒绝上传，不会再出现"上传成功、渲染时才变成红方块"。代价是 PNG 体积约为原 WebP 的 11 倍
  （实测 116KB → 1.3MB），已有的 WebP 立绘不受影响、仍由 FFmpeg 兜底读取
- 修复删除立绘/缩略图时路径解析错误导致文件删不掉（DB 存的是相对路径与 `/assets/...` 形式 URL，
  旧代码直接 `new File(path)` 在 Windows 上定位不到文件），现在读取与删除统一走 `ImageReader` 的解析规则

## 0.2.3


- 统一版本号来源：版本号只在 `demo/frontend/electron-react-app/package.json` 的 `version` 里维护，用 `node scripts/version.mjs <x.y.z> --write` 一次性同步到 `demo/pom.xml`、`application.yml` 的 `app.version` 和 `package-lock.json`
- 修正历史遗留的版本号不一致：此前 `package.json` 一直停在 0.1.0（安装包文件名与"关于"里显示的版本都落后于实际发版），后端 `pom.xml` 停在 `1.0-SNAPSHOT`；现在两者都是 0.2.3（后端 jar 为 `demo-0.2.3-SNAPSHOT.jar`）
- CI 发版前会校验 tag 版本与 `package.json` 版本一致，不一致直接失败，避免再发出文件名与版本号对不上的安装包
- 新增 `node scripts/version.mjs`（查看/修改/校验版本号）与 `node scripts/version.test.mjs`（版本工具自测）
